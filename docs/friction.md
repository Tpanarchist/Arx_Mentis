# Friction log

This is an append-only log. Add new dated paragraphs at the end; never rewrite an
older observation to make a later conclusion look inevitable. Corrections and
reinterpretations are new dated paragraphs. Each entry should identify the observed
difficulty, any recurring design tension, any leaked Python behavior, and any example
whose surface details obscure its underlying idea. State explicitly when one of
those fields was not observed.

Thesis work becomes warranted when the same nameable tension appears in three
genuinely unrelated programs, domains, or implementation situations. The trigger
permits synthesis; it does not require immediate thesis publication and does not
prevent earlier exploratory language. Repeated wording, examples, or patches from
one design episode count only once.
