# Documentation map

The documentation is part of the Stage 0 executable specification. It separates
decisions already needed for implementation structure from language choices that
remain deliberately open.

- `vision.md` — purpose, constraints, and non-goals.
- `bootstrap.md` — the Stage 0 contract and repository surface.
- `architecture.md` — pipeline boundaries and sibling backend paths.
- `development-process.md` — evidence, acceptance, and owned-value gates.
- `executable-specification.md` — the role and limits of Python.
- `ir.md` — discovery through high-level lowering attempts.
- `testing.md` — test categories and constructive generation risks.
- `roadmap.md` — ordering constraints and horizontal probes.
- `glossary.md` — shared working vocabulary.
- `dependencies.md` — dependency admission policy.
- `thesis.md` — intentionally unwritten synthesis.
- `friction.md` — append-only observations and the evidence trigger.
- `equivalence.md` — deliberately unfilled cross-backend obligations.
- `adr/` — accepted decisions and open questions.

Guidance living beside its subject is in `examples/README.md`,
`experiments/README.md`, `scripts/README.md`, and `tests/README.md`.
